# 交流编辑器与草稿恢复

评论的本机草稿同时保存文字、选区、回复目标和提及身份。键仍按服务地址、账号、草稿类型和目标隔离，兼容旧版只存文字/回复的记录；不会按昵称重新查找用户身份。

提及快照仅在本机保存`userId/start/end/label`，范围使用JavaScript的UTF16位置。恢复时验证范围、顺序、最多10项和标签原文；接口仍只提交`userId/start/end`。原文前后编辑会移动范围，修改标签内部则取消该提及。手动重新输入同一昵称不会自动恢复旧ID。

`inputDraftSave`可能早于交流脚本加载，也可能早于提及的input监听器执行。核心保存函数须保留原文匹配的已有快照；扩展的`editorDraft`读取前同步范围。选人完成后须再保存一次，否则最后选中的身份只存在旧DOM里。

`drawCompose`、评论/流评论重绘都主动合并一次编辑器增强，不等待后台轮询。选择器在重绘后仅可重新绑定相同草稿键、相同原文；发帖还要求同一个`UI.cp`实例，普通编辑面板要求相同面板归属。账号、帖子或正文已变化时不把旧选择写入新编辑器。

明确失败的待发送评论允许编辑，保留未改标签的身份及用户选择的回复目标。新提交键和正文通过既有IndexedDB `replace`事务一起替换旧记录，事务完成前不改内存中的原评论。写入失败保留原记录和正在编辑的输入；保存期间禁止再次保存、重试、移除。迟到确认不能关闭后来打开的面板。评论已成功发布或结果未知时，旧编辑面板也不能产生新提交键。

超时、断网或服务器异常显示“发送结果待确认”，保留原键进行幂等重试；明确拒绝才显示“未发送”。没有真实图标点击时，零值`DK.tap`不应进入450ms手势保焦窗口。

评论和私信输入框在宽度、字体或输入栏尺寸变化时重新测量，仍保留134px上限，超过上限允许内部滚动。高度反馈只更新留白，不递归触发长高；变化合并到下一帧，DOM移除后解绑观察器与字体/输入监听。手机和矮横屏的评论输入栏固定到底部，正文留白依据实际栏高，末条评论不会被长回复遮住；超宽矮窗口的底栏仍按帖子最大宽度居中。

评论恢复焦点前先注册提及按钮，浮动图标使用完整的控件集合；交流脚本迟到且输入框已聚焦时补注册并保留已有图标快照。发帖、帖子编辑和失败评论等可手动拉高的正文不因选择提及而被强制缩到聊天框高度；发帖正文保持原生内部滚动与手动高度。

验收入口：

- `node --test test/*.test.cjs tests/*.mjs`。
- `tests/editor-mentions.test.mjs`、`tests/composer-focus.test.mjs`：身份恢复、编辑范围、加载顺序、原子替换故障、迟到确认和焦点。
- `tests/editor-resize.test.mjs`：宽度/字体合并、纯高度反馈、清理及134px边界；`tests/editor-responsive-browser.js`：评论/私信转屏、末条评论可达、聚焦重绘、组字、减少动效、手动拉高、选区和身份、真实DOM移除清理。
- `tests/editor-drafts-browser.js`：独立发帖增强、选择期间重绘、刷新、真实File恢复、上传故障、假对象存储协议下发布及成功清稿。
- `tests/editor-failed-comment-browser.js`：真实IndexedDB事务中注入put失败，验证delete回滚；编辑后刷新和HTTP重试，以及已提交响应丢失后的单键去重。

`tests/communication-browser.js`每轮在隔离fixture注册一个新的`req_*`合成账号来验证首次消息请求，不复用已接受的会话；用户名保持在后端3～20字符合同内。

## 音频草稿与发布

音频读取绑定具体File、草稿实例、DOM面板、服务/账号和登录轮次。替换、移除或关闭时取消尚未开始的解码；已经进入浏览器的解码可能继续执行，但失去归属的结果不得写入`post:draft`、触发就绪事件或修改新界面。示例音频也使用独立任务键，完成后释放临时缓存；保留原有单路解码与草稿PCM保留策略。

解码失败保留原File并显示“重试读取”，发布及音频试听保持不可用，不回退成示例音轨。重试和刷新恢复会重新读取File。文件选择器清空自身值，用户可以再次选择同一个文件。读取存量草稿期间新选图片/音频视为用户编辑，优先保留，并允许关闭前保存。

图片和声音同时存在时保留两种File，提示移除其中一种后再发布，禁止按音频优先级静默忽略图片。旧混合草稿同样保留并提示，只有用户主动移除才改变附件。

上传ID另存文件来源标记（文件名、类型、大小、修改时间，示例另有版本）。该标记用于本地异步归属，不是内容校验或权限凭据。旧版没有来源标记或标记不匹配的音频草稿保留File，发布时重新上传；当前版本的失败重试、关闭及刷新继续复用已验证上传ID和原幂等键。

发帖每个异步阶段检查原账号和面板：保存、复核上传、直传、完成上传、提交作品、成功清稿。换号或关闭后不继续借用新会话发帖，迟到成功不关闭新面板或跳转新页面。已经发给服务器的请求仍可能成功，保存的requestKey用于后续幂等确认。`liveUpload`也在申请上传、PUT和完成请求之间检查服务/会话及可选调用方归属。

验证入口：`tests/audio-drafts.test.mjs`、`tests/audio-publish.test.mjs`执行实际页面函数，使用受控解码器/网络验证竞态与错误；`tests/audio-drafts-browser.js`用合成两秒WAV、真实IndexedDB与本机后端验证解码、恢复、重试、上传元数据及成功清稿。浏览器只解码，不播放设备声音。返回的`media.audioMeta.duration/peaks`是客户端展示数据，不能作为媒体安全校验。

## 原生视频

`scripts/native-video-v1.js`处理视频MIME、临时读取及原生播放器。选择MP4/MOV/WebM，文件不超过500MB（服务端仍以实际配置限制为准）；缺少MIME时只按这三种扩展名补齐。保留原File，读取尺寸/时长并自动截取JPEG封面，不生成假视频或假声音。封面暂不可取时允许保留视频，未知时长显示`--:--`。读取失败、超时或不支持格式均保留File供重试/移除。

视频File、派生封面Blob、各自上传ID和文件来源一起进入本机草稿。替换/移除/关闭取消旧任务并释放临时地址，迟到结果不回填。恢复后重新读取File，来源匹配才复用上传ID；上传视频与封面分别保存进度，发布失败保留原幂等键。视频与图片组、声音或外链混合时提示用户选择，不静默丢附件。

发布沿用`post_video`和`post_image`，视频帖新媒体合同为一个视频、至多一张派生封面；无文件时需视频链接。作者可保留视频/封面修改文字，API也支持替换视频并走既有审核。既有旧视频媒体完全保留时继续允许修改文字。前端本批实现文字编辑及保留/移除已有媒体，视频文件替换表单仍待单独补齐。

草稿和帖子详情使用真实`video controls playsinline`。草稿预览原有父层不接收指针，原生播放器子层单独开放点击；处理中/失败/发布中仍受inert限制。真实草稿不再指向不存在的服务器`post-draft`。重绘时保留整个播放器及其重试监听，正文编辑、点赞不替换播放中的元素。退出页面、换会话立即停止旧媒体；access正常刷新不改归属。视频与生成器、真实音频、其它原生媒体互斥，并在缓冲不足时为播放让出字体带宽。

播放失败只自动补读一次签名；随后提供显式重试。等待补读时可取消，关闭、换号或取消后的迟到地址不能抢播。真实外链视频明确提供“在原网站观看”，只打开http(s)地址，不以原型画面/音轨冒充真实播放；纯原型演示保留原有示例。分享及历史缩略图优先使用视频派生封面。

验证入口：`tests/native-video.test.mjs`、`tests/native-video-drafts.test.mjs`和`tests/native-video-browser.js`。浏览器使用本机Canvas/MediaRecorder生成并固定的无音轨WebM夹具，通过鼠标点击原生控件验证播放、真实帧尺寸、草稿/上传恢复、签名补读与取消、会话更换、互动重绘和文字编辑。竖向媒体也单独生成并检查布局。

浏览器脚本只针对本机合成fixture，`bucket.test`使用拦截的假对象存储，不能当作生产S3/COS或真实媒体交付验收。转屏使用Chrome视口；MP4/MOV的真实编解码器、iOS/Android真机、软键盘和音质尚未验收。跨设备草稿、原生视频竖向流切条、视频替换前端及语音消息继续待实施。
