# 交流编辑器与草稿恢复

评论的本机草稿同时保存文字、选区、回复目标和提及身份。键仍按服务地址、账号、草稿类型和目标隔离，兼容旧版只存文字/回复的记录；不会按昵称重新查找用户身份。

提及快照仅在本机保存`userId/start/end/label`，范围使用JavaScript的UTF16位置。恢复时验证范围、顺序、最多10项和标签原文；接口仍只提交`userId/start/end`。原文前后编辑会移动范围，修改标签内部则取消该提及。手动重新输入同一昵称不会自动恢复旧ID。

`inputDraftSave`可能早于交流脚本加载，也可能早于提及的input监听器执行。核心保存函数须保留原文匹配的已有快照；扩展的`editorDraft`读取前同步范围。选人完成后须再保存一次，否则最后选中的身份只存在旧DOM里。

`drawCompose`、评论/流评论重绘都主动合并一次编辑器增强，不等待后台轮询。选择器在重绘后仅可重新绑定相同草稿键、相同原文；发帖还要求同一个`UI.cp`实例，普通编辑面板要求相同面板归属。账号、帖子或正文已变化时不把旧选择写入新编辑器。

明确失败的待发送评论允许编辑，保留未改标签的身份及用户选择的回复目标。新提交键和正文通过既有IndexedDB `replace`事务一起替换旧记录，事务完成前不改内存中的原评论。写入失败保留原记录和正在编辑的输入；保存期间禁止再次保存、重试、移除。迟到确认不能关闭后来打开的面板。评论已成功发布或结果未知时，旧编辑面板也不能产生新提交键。

超时、断网或服务器异常显示“发送结果待确认”，保留原键进行幂等重试；明确拒绝才显示“未发送”。没有真实图标点击时，零值`DK.tap`不应进入450ms手势保焦窗口。

验收入口：

- `node --test test/*.test.cjs tests/*.mjs`。
- `tests/editor-mentions.test.mjs`、`tests/composer-focus.test.mjs`：身份恢复、编辑范围、加载顺序、原子替换故障、迟到确认和焦点。
- `tests/editor-drafts-browser.js`：独立发帖增强、选择期间重绘、刷新、真实File恢复、上传故障、假对象存储协议下发布及成功清稿。
- `tests/editor-failed-comment-browser.js`：真实IndexedDB事务中注入put失败，验证delete回滚；编辑后刷新和HTTP重试，以及已提交响应丢失后的单键去重。

浏览器脚本只针对本机合成fixture，`bucket.test`使用拦截的假对象存储，不能当作生产S3或真实媒体交付验收。本轮没有跨设备草稿、原生视频直传或语音消息的验收证据。转屏后的长草稿高度与物理图标布局仍单独跟进。
