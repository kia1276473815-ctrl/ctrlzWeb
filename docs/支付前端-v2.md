# 支付前端 v2

前端沿用现有订单和付款面板，对接 `GET /config.trade` 的 `contract: "ctrlz-trade-v2"`。`live` 合同必须提供布尔能力及 `channels: [{channel, scenes}]`；缺失或异常合同关闭新交易。旧 `disabled/mock` 合同保持兼容，历史 `legacy` 资金操作继续只读。

- 首期真实支付只支持现金；隐藏代金券并明确发送 `useVoucher:false`。微信按终端使用 `native/h5/jsapi`，支付宝使用 `page/wap`，仅显示服务端提供且当前环境支持的渠道。微信内不能直接跳支付宝时只显示微信渠道。
- `POST /orders` 创建订单，或用户手动点击“继续付款”调用 `POST /orders/{id}/pay`。请求带 `paymentScene`，返回地址由服务端配置生成；前端不提交任意返回网址。
- `OrderView.payment` 提供 `attemptId/channel/scene/status/expiresAt/action`。二维码在本地生成；跳转地址检查 HTTPS 与官方渠道域名；JSAPI 参数只交给微信桥接。调起成功或取消均不能据此授予已购。
- 查询始终使用 `GET /orders/{id}`，每 2.5 秒一次，前台持续至多 5 分钟。页面隐藏暂停，关闭面板不撤销订单。只保存服务地址、账号、订单 ID 和时间的恢复标记；返回或重新打开页面后查询原订单，不重放付款 POST。
- 创建请求的提交键与返回订单 ID 绑定；`pending/unknown` 保持同键，服务端确认 `paid/refunded/closed/failed` 后才释放对应键。超时关闭或退款后再次购买会产生新键，迟到旧结果不能清除新的购买意图。
- 网络异常保留恢复标记并提示先查询，跨账号或换服务的迟到响应丢弃；只有服务端确认订单 `paid` 才展示付款成功和已购。关闭、失败或退款显示对应状态。
- `mock` 订单存在 `payment` 时展示“模拟付款成功（不会扣款）”，显式调用本地开发入口 `POST /pay/mock/{attemptId} {kind:"payment"}`，然后 GET 确认。不会展示 mock 付款码，也不会自动触发模拟成功；旧同步 mock 不受影响。

二维码库为 [Project Nayuki QR Code generator](https://www.nayuki.io/page/qr-code-generator-library)，MIT 许可全文保留在 `vendor/qrcodegen.js`。Service Worker 将该组件与页面同步预缓存，付款链接不发送外部二维码生成服务。

验证：`node --test tests/*.test.mjs`。`tests/live-payment-flow.test.mjs` 覆盖状态推进、网络未知、跨账号、返回恢复、JSAPI 取消、live 禁券和异步 mock。`tests/live-payment-browser.js` 使用隔离 DTO 检查二维码与支付宝跳转面板的 12 尺寸 × 双主题，并检查断网和 JSAPI 取消；不代表真实渠道联调完成。
